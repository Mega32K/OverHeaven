# illusionTp 深度扫描传送设计

状态：用户已确认深度灰色方案及两种命令用法；功能说明已同步当前实现，实际游戏表现待实测。
更新日期：2026-10-30，Asia/Shanghai。

## 用户已明确的要求

- 新增独立命令 `illusionTp`，为目标玩家提供带特效的传送。
- 参考 EndingLibrary `DepthTestPostEffect` 的深度扫描波外观。
- 第一道波扫过的画面转为深灰色，覆盖所有场景像素，包括天空。
- 第一道波扫过的每处场景立即开始独立淡灰，约 5 tick 后成为纯灰；等所有像素完成扫描与淡灰并实际绘制纯灰帧后才传送。
- 传送后重新发出第二道波；扫过的区域显现目的地的实际场景。
- 扫描从慢逐渐加快至原有速度；全速基准为参考效果的三倍时间轴。
- 沿用本会话的最小必要验证要求，不扩展大量检查，不启动游戏、不打包、不替换实例。

## 已确认的设计

- 用户于 2026-10-30 确认深度灰色扫描：去除原场景纹理与颜色，以真实相机到表面的距离按 `exp2(-距离格数 / 32)` 混合近灰 `#707070` 和远灰 `#242424`，保留近亮远暗的形体轮廓；天空为 `#242424`，覆盖完全不透明。

- 各表面按自身扫到时间戳独立计时：从实际扩散曲线反算 hitTime，按 elapsed - hitTime 进行 0.25 秒 smoothstep 渐变，截止时刻为 hitTime + 0.25 秒。取消波后距离比例插值和整屏统一强度；转头时按真实表面距离对应时间，不保存固定屏幕像素历史。

- 遮蔽为“原场景 → 深度图 → 纯灰”；抵达后的显现反过来，为“纯灰 → 深度图 → 原场景”。显现的材质恢复边缘跟在局部深度淡入之后；两者保持向外传播与既有加速曲线。覆盖查询在两道波中都等待局部截止时刻与 glitch 边缘通过，绘制完整端点帧后才确认传送或结束。目的地仍需连续两帧就绪；就绪丢失立即纯灰等待，恢复后重启。

- 用户于 2026-10-29 要求扫描从慢逐渐加快至原有速度。实现为前 1.5 秒将推进倍率从原来的 20% 平滑提升至 100%，之后沿用三倍时间轴与平方扩散；对倍率积分，避免衔接时半径或速度突变。遮蔽扫描与显现扫描分别重新缓启动，glitch 的播放时钟保持不变。

- 波前外观保留参考效果的白色亮边与波前附近短暂的故障/色散。用户于 2026-10-29 补充要求恢复 glitch，且亮边厚度与示例一致：沿用 20 次光谱采样、`length(oneTexel) * 24.0` 宽度、中心向外的原始衰减和 `4.5 × width` 故障范围。波前经过后，遮蔽扫描留下不透明深度灰色轮廓，显现扫描留下目的地实际场景；用户已于 2026-10-29 确认。

- 扫描仅覆盖世界场景与天空。第一人称手部、手持物以及 HUD（准星、血条、快捷栏、聊天）均保持正常显示，不参与遮蔽与显现扫描；用户已于 2026-10-29 确认。

- 操作限制：从遮蔽扫描开始，到显现扫描结束，锁定玩家位置并允许自由转动视角。正式传送时将锁定位置从起点切换到目的地；转场结束或取消后解除锁定。用户已于 2026-10-29 确认禁止移动、允许转动视角。

## 已确认的命令用法

沿用现有传送命令的玩家选择器与坐标/实体目的地形式：

```text
/illusionTp <targets> <x> <y> <z>
/illusionTp <targets> <destination>
```

`targets` 为玩家选择器或玩家名；`destination` 为单个实体。扫描先缓启动，再达到参考效果三倍时间轴的原有推进倍率，由全景遮蔽与目的地就绪状态衔接传送和显现。此命令不需要 `in`、`duration`、`out` 参数。用户已确认上述命令用法，并授权按已记录方案开始实现。

用法、实现边界与验收项见 `docs/ILLUSION_TP.md`；验证记录见 `audit/illusiontp-2026-10-29-impl/VALIDATION.md`。未打包、启动游戏或修改实例。
