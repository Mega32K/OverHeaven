# 近距离透镜源不连续保护与内侧降饱和（2026-10-26）

## 已观察事实与证据边界

用户截图表现为靠近中心抬头时地形/天空出现大片扇形条带。当前 shader 已经有屏外源 smoothstep 回退，因此没有重复增加同一逻辑。检查 composite.fsh 发现：深度状态匹配的有效邻居会直接平均 warped UV，未检查邻居之间的源位置是否跨越不连续区域。

新增受控 GPU 反例：左右邻居分别指向 UV.x=0.2 和 0.8，中间的 UV.x=0.5 放置不同颜色。修改前错误采到了中间颜色；before-negative.log 记录了断言失败。修改后同一测试通过。这确认了该插值缺陷，但没有在真实 Minecraft 场景中复现用户截图，因此不能认定它是截图的唯一原因。

## 采用的修复

在现有四点重建循环中累计有效源的最小/最大 UV，并保存最大有效权重的邻居。有效性继续要求场景深度与核心状态匹配，新增排除非有限 UV 和几乎零权重。

每轴阈值为 clamp(4 / 求解分辨率, 0.004, 0.025)，使用归一化源 UV：保留通常的局部平滑，同时给不同质量档设置有限容差。超过阈值时选择主导邻居的 UV 和该邻居自身的最小合法源距离，绝不混用其他邻居的距离。平权时按固定遍历顺序选择，避免随机变化。连续区域仍插值；无有效源时原有回退生效。后续屏幕边界和完整采样足迹的前景深度检查仍执行。

没有新增逐像素积分、额外 pass、目标纹理、配置、命令或网络字段。盘面、辉光、透明分段和 EndingLibrary/Oculus 调用时序未改变。

限制：主导邻居切换可能在强拉伸区域出现离散感；阈值是视觉保护策略，不是物理连续性证明。屏幕空间仍没有屏外世界颜色。需在原截图位置观察缓慢抬头/左右转头，确认大片条带消失，并检查切换边缘是否可见；若仍有异常，继续检查弯曲路径与背景深度求交，不能靠扩大回退范围宣称修复。

## 饱和度曲线

按已确认范围处理核心边界 Radius 到盘内缘 Inner 的内侧过渡区。t=clamp((r-Radius)/(Inner-Radius),0,1)，色度保留系数为 0.5*t*t*(3-2*t)。中心端完全去色，外缘端保留原颜色 50% 色度；这是原色度的保留系数，不是强制 HSV 饱和度等于 0.5。

用 RGB 加权亮度 (0.2126, 0.7152, 0.0722) 与原色混合，保持该亮度不变。应用于局部薄雾及核心直接细边/辉光源的同一颜色函数。薄雾在过渡区之外夹紧到 50%；普通盘面从 Inner 以外开始，原有盘面配色不变。核心内部继续黑色吸收，不额外填充灰色。色度曲线测试覆盖 0、1/4、1/2、3/4、1 和逐点亮度守恒。

术语记录在 CONTEXT.md。此处是可逆的局部着色器调整，无需建立不可逆架构决策 ADR。
