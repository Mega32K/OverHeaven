# pixelTp 像素排序传送

```mcfunction
/pixelTp <targets> <x> <y> <z> <in> <duration> <out>
/pixelTp <targets> <destination> <in> <duration> <out>
```

- `targets`：玩家名或玩家选择器，如 `@s`、`@a`。
- `x y z`：目的地坐标，支持原版绝对、相对及局部坐标，按命令执行位置解析。
- `destination`：单个实体名或实体选择器；执行命令时记录该实体的维度、位置与朝向。
- `in`：进入转场的秒数；`duration`：到达并绘制目的地画面后的全遮蔽保持秒数；`out`：退出转场的秒数。
- 三个时长均为必填，范围 0～60 秒，支持小数，按 20 ticks/秒取整；非零时长至少 1 tick。
- 命令权限等级 2。服务端与目标客户端均须具有本版本的 pixelTp 功能。

示例：

```mcfunction
/pixelTp @s 100 80 -200 0.6 0.2 0.6
/pixelTp @a @e[type=minecraft:armor_stand,tag=arrival,limit=1] 0.8 0.3 0.8
/execute in minecraft:the_nether run pixelTp @s 0 80 0 0.8 0.2 0.8
```

## 视觉与时序

原创实时 GLSL 实现参考 AE Pixel Sorter 的“亮度阈值区间、条带内排序、横向拉伸、条带增长”效果。画面中的亮部先形成横向色条，随后阈值降低、更多区域被拉长，错开的条带尾沿将画面擦成黑幕。传送在完整遮蔽之后执行，目的地恢复时反向展开。

为控制实时开销，排序种子区间上限为 128 个原始像素，先按亮度阈值分段，再在段内稳定排序；拉伸可以超过种子区间。此实现针对传送制作固定风格，不加载 AE 插件，也不宣称逐像素复现插件的全部参数或预设。

进入转场完成并实际绘制全遮蔽帧后，客户端才确认允许传送。服务端只接受当前玩家当前请求的随机 ID，不接受客户端提供坐标。目的地维度与区块到达且至少绘制一帧后开始计 `duration`，随后执行 `out`。网络与加载等待可能延长实际总时间。零时长仍保留必要的遮蔽帧和同步过程。

不冻结玩家、不赋予无敌或修改飞行状态。同一玩家已有转场时拒绝新请求；死亡、断线、意外切换维度、资源错误和超时会清理。沿用 Forge 的传送命令事件，其他模组仍可取消或调整传送。

## 渲染接入

在原版世界和后处理完成、EndingLibrary 2.2.1fix 的 `GuiGraphics` 构造前后处理之后、HUD 绘制之前合成。复用已有 GL 状态保护，使用私有全分辨率纹理，不写世界深度、不重复曝光或 gamma 转换，也不替换宿主后处理链。结束、断线、资源重载和退出客户端时释放 GPU 资源。

## 验证边界

Java 编译、资源处理及独立着色器试绘分别记录于 `audit/pixeltp-2026-10-28/`。旧版竖向效果的 `gpu/` 预览和排序检查仅为迭代记录；最终横向阈值拉伸效果见 `gpu-ae/`。

未启动 Minecraft、未生成或安装新 JAR。仍需在游戏内验收实际条带观感、网络延迟、跨维度加载，以及当前 Embeddium/Oculus/Complementary/EndingLibrary 组合的显示与性能。
