# OverHeaven 黑洞渲染效果与性能审查

审查日期：2026-10-29。对象为当前工作树中的黑洞本体、终场主体与星空，以及普通/Oculus 接入路径。本轮只生成分析，不修改渲染实现。

## 结论

这套实现已超出简单的屏幕贴图特效，具备相机相对坐标、场景深度分层、有限步积分、辉光金字塔及宿主光影适配。但其画质和性能上限仍明显受制于几个结构选择：**屏幕空间背景取样、单个透明界面的重建、每个黑洞重复处理整屏缓冲，以及重建失败后隐藏在合成阶段的完整积分。**

目前适合把它定位为“针对特定宿主、以单个主体为主要目标的艺术化黑洞渲染器”。源码不足以证明复杂遮挡下始终稳定，也不足以证明高分辨率、多主体、终场过渡具有稳定帧预算。不能把已有独立预览或旧版验证当作当前游戏画质与帧率结论。

证据等级：**确认**指当前源码或归档内容直接可见；**推导**指由算法得到的限制或成本；**待实测**指缺少当前游戏帧捕获/计时，不能断言已发生或确定严重程度。P1 表示应优先解决的高影响风险，不等同于已经复现的崩溃；P2 表示次优先画质、稳定性或可维护性问题。

## 2. 渲染流程与成本来源

普通路径：世界渲染开始获取实际相机 → 透明绘制前复制不透明颜色和深度 → 透明绘制后采集表面信息 → AFTER_LEVEL 逐个黑洞复制场景、积分、辉光和合成。

Oculus 路径：在指定光影缓冲阶段采集 → 折射前合成后侧辐射 → 另存前侧辐射 → 宿主 composite1 后补入前侧。前后侧辉光分别计算。

终场路径：世界后处理后的显示空间合成；先绘制低分辨率银河、全分辨率星点/星轨，再通过独立 BlackHoleRenderer 绘制宇宙中的主体。覆盖率介于 0 与 1 时世界和宇宙路径可能同时工作；覆盖率达到 1 后有 skipWorld，不能说全程都重复渲染。

## 3. 渲染效果：严格批判

### V1 / P1：透镜的可见性信息不足，无法保证世界景物连续性

**确认：**[field.glsl:90](E:/CollapsingWorld/System-e/OverHeaven/mod/src/main/resources/assets/overheaven_foliage_compat/shaders/blackhole/field.glsl:90) 的 environmentLens 输出投影 UV；[composite.fsh:29](E:/CollapsingWorld/System-e/OverHeaven/mod/src/main/resources/assets/overheaven_foliage_compat/shaders/blackhole/composite.fsh:29) 只从当前 Scene/Opaque 取样，并在屏幕边缘、深度不可信或透明源无法解析时回退到原背景。边缘权重从约半像素到 0.035 UV 范围渐变。

**推导：**屏幕外、前景后被遮住的世界内容没有被重建；转动相机时，同一背景是否能参与透镜会随屏幕可见性改变。深度保护避免了明显拉入前景，却也意味着某些区域的弯曲会退化、减弱或消失。这是明确的质量上限，不能用更多积分步数解决。

**应优先验证的表现：**黑洞贴近屏幕边缘、门框/树叶遮挡黑洞、玩家绕过遮挡物时，是否出现“局部透镜突然失效”和背景粘连。建议先增加可视化的源拒绝/回退覆盖率，再决定是否值得引入额外背景信息；不默认增加完整离屏世界渲染。

### V2 / P1：透明层是一个聚合界面，复杂多层透明无法被准确重排

**确认：**[field.glsl:122](E:/CollapsingWorld/System-e/OverHeaven/mod/src/main/resources/assets/overheaven_foliage_compat/shaders/blackhole/field.glsl:122) 只使用 OpaqueDepth 和 SurfaceDepth 切分 front/back；[copy.fsh:13](E:/CollapsingWorld/System-e/OverHeaven/mod/src/main/resources/assets/overheaven_foliage_compat/shaders/blackhole/copy.fsh:13) 由 alpha 或 RGB 构建聚合透射；[composite.fsh:141](E:/CollapsingWorld/System-e/OverHeaven/mod/src/main/resources/assets/overheaven_foliage_compat/shaders/blackhole/composite.fsh:141) 用 host − transmission × opaque 求表面残余。

**推导：**一层玻璃和不透明背景的简单场景与该模型较匹配；多层玻璃、水面叠玻璃、粒子与透明方块交错时，聚合颜色和一个深度值不包含每一层的位置与透射顺序。已存在的深度拒绝不能补出这些丢失的信息。宿主若还引入反射、折射或后续颜色处理，残余分解更不能被视作通用准确重建。

不应直接指控“所有水面必然穿帮”；准确结论是**复杂透明层的正确性没有模型保证**。不建议简单增加全屏模糊掩盖问题，应界定支持范围并优先测两层交错情况。

### V3 / P2：核心、盘面与背景透镜使用不同的几何近似

**确认：**[field.glsl:127](E:/CollapsingWorld/System-e/OverHeaven/mod/src/main/resources/assets/overheaven_foliage_compat/shaders/blackhole/field.glsl:127) 以直视射线求核心命中，并据此确定积分终点；149 行起盘面路径再进行弯曲步进；环境透镜另用弱场方向映射；[composite.fsh:145](E:/CollapsingWorld/System-e/OverHeaven/mod/src/main/resources/assets/overheaven_foliage_compat/shaders/blackhole/composite.fsh:145) 又用解析指数函数补核心边缘亮线。

**推导：**这些机制能共同形成艺术轮廓，但不共享一条完整的弯曲光线路径。高 lensing、接近核心或极端盘面倾角时，可能出现核心边界、盘面扭曲和背景弯曲不完全一致的视觉关系。问题是几何一致性，而非“没有做到科学模拟”。应固定几个极端视角检查轮廓和遮挡，不能仅凭正面参考图通过。

### V4 / P2：半分辨率重建以拒绝和回退换取正确性，边缘稳定仍无保证

**确认：**[composite.fsh:84](E:/CollapsingWorld/System-e/OverHeaven/mod/src/main/resources/assets/overheaven_foliage_compat/shaders/blackhole/composite.fsh:84) 以四个低分辨率样本重建，对深度差和核心内外关系进行过滤；权重不足时在 104 行直接 integrate(texCoord)；透镜源跨越不连续阈值时改用最大权重样本。

**推导：**这比无条件双线性放大严谨，但在细栅栏、叶片、小亮线和核心边缘，样本选择会随亚像素移动变化。可能出现锐度变化、闪烁或“重建/全量求解”切换。当前这一路没有自己的历史重投影和时间稳定机制；宿主 TAA 能否改善，取决于接入阶段与运动信息，未实测。

### V5 / P2：长时间旋转靠不断加大 mip 足迹抑制闪烁，细节会随运行时间退化

**确认：**[field.glsl:65](E:/CollapsingWorld/System-e/OverHeaven/mod/src/main/resources/assets/overheaven_foliage_compat/shaders/blackhole/field.glsl:65) 的旋转采用随半径变化的角速度，74 行足迹包含 abs(Time × Rotation) 项，diskLookup 以此提高 LOD；[BlackHoleRenderer.java:267](E:/CollapsingWorld/System-e/OverHeaven/mod/src/main/java/com/mega/overheaven/foliagecompat/blackhole/client/BlackHoleRenderer.java:267) 将时间取模 1048576 秒。

**推导：**相机不动、参数不变且 Rotation 非零时，径向剪切足迹仍会随 Time 增长，盘面越跑越容易使用更粗 mip。该防闪烁处理有合理性，但把时间稳定性问题转成了长期纹理损失；时间取模还留下约 12.14 天相位重置边界。是否在几十秒、几分钟或更久后肉眼明显，需要按实际盘面尺度取样。

优先比较相同视角下 t=0、60、600、3600 的纹理对比；若退化明显，优先调整物质更新/剪切寿命模型，而不是简单降低 LOD 后重新引入闪烁。

### V6 / P2：显示空间与宿主光影空间的观感一致性没有统一保证

**确认：**[composite.fsh:155](E:/CollapsingWorld/System-e/OverHeaven/mod/src/main/resources/assets/overheaven_foliage_compat/shaders/blackhole/composite.fsh:155) 普通路径把 light 映射为 light/(1+light)，再加到 baseColor；Oculus 分层路径保留宿主颜色处理，[foreground.fsh:8](E:/CollapsingWorld/System-e/OverHeaven/mod/src/main/resources/assets/overheaven_foliage_compat/shaders/blackhole/foreground.fsh:8) 还存在与指定光影相配的 2.2 次幂转换。本轮检查实际光影 ZIP 的 shaders/program/composite1.glsl，第 318 行确有 color = pow(color, vec3(2.2))。

**推导：**不能简单把该 2.2 转换判成重复 gamma 错误；但普通路径的逐通道压缩与光影路径的宿主映射并不等价，强光颜色、亮部层次与辉光范围可能不同。普通路径最后相加也不保证低于 1，实际截断取决于目标格式和后续处理。应明确风格一致性容差，而不是承诺开关光影完全相同。

### V7 / P2：多个相交主体只做整体距离排序

**确认：**[BlackHoleRenderer.java:65](E:/CollapsingWorld/System-e/OverHeaven/mod/src/main/java/com/mega/overheaven/foliagecompat/blackhole/client/BlackHoleRenderer.java:65) 按中心距离排序；每个主体独立积分、逐次合成，Opaque/Surface 深度仍是捕获的世界深度。

**推导：**对空间分离的少数主体是可接受折中；相交吸积盘或前后关系在屏幕内变化时，整体中心排序不能替代逐像素体积排序。先前主体也没有变成完整的新世界深度层。项目说明本就以同屏一个为基准，不应把最多 256 条记录理解为 256 个重叠主体具备正确效果与性能。

## 4. 渲染性能：可量化的成本

### P1：每个主体都有整屏固定成本，裁剪只覆盖部分步骤

[BlackHoleRenderer.java:193](E:/CollapsingWorld/System-e/OverHeaven/mod/src/main/java/com/mega/overheaven/foliagecompat/blackhole/client/BlackHoleRenderer.java:193) 在每个黑洞循环里整屏复制 scene，并清理四个 solution 附件，然后才对积分启用 scissor。[GlBloom.java:46](E:/CollapsingWorld/System-e/OverHeaven/mod/src/main/java/com/mega/overheaven/foliagecompat/blackhole/client/GlBloom.java:46) 每个层级也先整目标清理，再裁剪绘制。

因此一个屏幕面积很小、甚至被墙体完全挡住但仍通过投影裁剪的黑洞，仍可能支付固定缓冲操作成本。shader 中的深度提前退出可以省掉积分，不能撤销已经提交的整屏复制与 clear。还必须注意：GPU 可能将 clear 实现为快速清除，不能把名义清理字节数直接当实测显存带宽。

默认 1080p 下，单次 solution 清理覆盖的附件容量约 23.73 MiB。场景复制若按 RGBA8 源读取 4 字节与 RGBA16F 目标写入 8 字节计算，名义颜色数据量又约 23.73 MiB；HDR 源、更复杂格式及深度读取会不同。这些是逻辑工作量，未计压缩、缓存，也不是 PCIe 传输量或实际 DRAM 计数。

改进顺序：先测小主体/完全遮挡场景的成本占比；再考虑有效区域复制、局部或延迟清理、在保证邻域采样初值正确的前提下缩小附件工作范围。不能直接删 clear，否则重建和 bloom 可能读到上一帧残留。

### P1：重建回退能显著放大积分预算，而且 Oculus 可能重复触发

设全屏像素数 P、求解线性比例 s、步数 N、主体覆盖率 A。仅第一遍积分的循环预算约为 P × s² × A × N。默认 s=0.5、N=48；设合成区域中回退比例为 f，单次合成又可能增加 P × A × f × N。

当 A=1 且 f=1 的极端情况下，默认路径从 12P 步预算升到 60P；Oculus 两次合成都执行同一重建逻辑时，预算可到 108P。**这是条件性上界模型，不代表每帧真的执行到该步数**：深度拒绝、核心截断、透射提前终止和终场分支都会改变结果。

| 分辨率 | low：0.375 / 24 | balanced：0.5 / 48 | high：0.75 / 96 |
|---|---:|---:|---:|
| 1920×1080 | 7.00 百万 | 24.88 百万 | 111.97 百万 |
| 2560×1440 | 12.44 百万 | 44.24 百万 | 199.07 百万 |
| 3840×2160 | 27.99 百万 | 99.53 百万 | 447.90 百万 |

表格是单主体满屏第一遍的积分步预算，排除合成回退和其他 pass。high 相对 balanced 是 **4.5 倍**，不是 2 倍；4K balanced 与 1080p balanced 又相差 4 倍。

普通盘面在有效气体区每步有两次 quadrature，每次 diskMaterial 有四次纹理读取，即最多八次盘面纹理读取，并带有指数、幂和三角运算。不能用“一步等于一次廉价采样”估计成本。证据：[field.glsl:76](E:/CollapsingWorld/System-e/OverHeaven/mod/src/main/resources/assets/overheaven_foliage_compat/shaders/blackhole/field.glsl:76)、[field.glsl:144](E:/CollapsingWorld/System-e/OverHeaven/mod/src/main/resources/assets/overheaven_foliage_compat/shaders/blackhole/field.glsl:144)、[field.glsl:164](E:/CollapsingWorld/System-e/OverHeaven/mod/src/main/resources/assets/overheaven_foliage_compat/shaders/blackhole/field.glsl:164)。

最优先新增的诊断量应是回退像素比例和各 pass GPU 时间；之后再决定边缘单独求解、复用重建结果或自适应分辨率是否划算，不应先全局提高 Steps。

### P1：默认辉光是 7-pass 链，Oculus 每主体两条链

[GlBloom.java:13](E:/CollapsingWorld/System-e/OverHeaven/mod/src/main/java/com/mega/overheaven/foliagecompat/blackhole/client/GlBloom.java:13)：balanced 有 4 层 down 与 3 层 up，共 7 次绘制。[BlackHoleRenderer.java:200](E:/CollapsingWorld/System-e/OverHeaven/mod/src/main/java/com/mega/overheaven/foliagecompat/blackhole/client/BlackHoleRenderer.java:200) 与 208 行分别触发后侧和前侧辉光。

只计算主循环中的 copy、solve、bloom 和 composite，默认有辉光时普通路径为每主体 **10 次绘制**，Oculus 为 **18 次绘制**；不含共有捕获、alpha 恢复、折射后补合成、远景 glare、终场几何等额外步骤。low/high 单条 bloom 分别为 5/9 次。

而且 [bloom.fsh:54](E:/CollapsingWorld/System-e/OverHeaven/mod/src/main/resources/assets/overheaven_foliage_compat/shaders/blackhole/bloom.fsh:54) 的提取对每输出像素执行 4×4 次 extractLight；后续 3×3 taps 中每个 guarded 又手动读四个邻居。它不是几个便宜的线性 texture 调用。两条辉光链有透明分层上的用途，不能不顾深度语义合成一条；应先计时，再评估共享降采样、打包分层辐射或减少重复深度重建。

### P1：缓冲占用不小，终场过渡存在双渲染器常驻

[BlackHoleRenderer.java:24](E:/CollapsingWorld/System-e/OverHeaven/mod/src/main/java/com/mega/overheaven/foliagecompat/blackhole/client/BlackHoleRenderer.java:24) 与 [BlackHoleRenderer.java:286](E:/CollapsingWorld/System-e/OverHeaven/mod/src/main/java/com/mega/overheaven/foliagecompat/blackhole/client/BlackHoleRenderer.java:286)：世界实例的基础附件占用为 (40 + 48s²)P 字节，40 来自 opaque 12、transparent 12、scene 8、foreground 8，solution 为每求解像素 48 字节。普通路径也会分配 foreground，尽管它主要服务 Oculus。

终场独立主体实例基础为 (32 + 48s²)P；FinaleRenderer 另外分配全尺寸 scene/cosmicScene 与 s 比例 stars，即 (16 + 8s²)P。默认 s=0.5，若两套实例均已初始化并同时保留，合计 114P 字节。

**这不是总显存数字。**未计 bloom、glare、因果背景、盘面纹理、深度/驱动额外开销、宿主场景和光影附件。NASA 4096×2048 RGB9_E5 的基础贴图还约 32 MiB。附件由每个渲染器实例复用，因此不能把表格再乘黑洞数量；多主体增加的是重复 pass 与读写，通常不会按主体数复制这些附件。

这些附件在 close/resize 时释放，源码没有证明泄漏。但世界渲染器从有主体变为无主体时，begin 的提前返回不会主动回收大附件，显存会留到资源重载、世界切换/退出等清理节点。应区分“保留缓存”和“泄漏”；可优先按需分配 foreground，并评估长时间空闲后的回收策略。

## 5. 兼容性评价

## 6. 建议实施顺序

1. **先补性能归因。**在独立输出目录采集分段 GPU 时间、CPU 提交时间、回退像素比例和峰值；先比较无黑洞/小主体/满屏主体/完全遮挡主体。这里只提出后续工作，本轮不增加或运行该测试。
2. **再减少重复工作。**优先处理整屏 copy/clear、Oculus 两次合成重复重建、按需 foreground 分配。保持前后层与宿主折射边界，不用合并全部图层换取表面上的帧率。
3. **修画质稳定性。**优先细遮挡边缘、屏幕边缘透镜退化、长期盘面剪切 LOD，然后才调美术亮度与辉光。
4. **单独压终场峰值。**围绕覆盖率过渡和长星轨设预算，避免优化稳定段后仍在演出高潮卡顿。
5. **最后才扩展多主体或宿主组合。**当前先以一个主体与已审计光影包把质量边界落实。

最低限度的真实游戏取证应包含：固定相机与运动相机、墙/栅栏/叶片遮挡、单层与双层透明、1080p/1440p/4K 三档质量、世界到终场过渡、同屏多个分离/相交主体，以及普通路径与受支持光影组合。这里只列辨别上述假设所需场景，不把它们标为已通过，也不授权安装或启动游戏。
