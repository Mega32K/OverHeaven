# 世界轴远景扭转：worldWarp

独立的世界顶点扭转效果。支持固定场景轴和跟随玩家眼部位置两种模式；轴方向由命令确定，转头、第三人称或演出摄像机不会带动轴旋转。只有显示几何改变，碰撞、移动、射线交互和方块坐标保持原状。

## 命令

需要权限等级 2，支持玩家选择器和命令方块，两端安装匹配版本的本模组。worldWarp 通道协议现为 2，旧版协议 1 不能与此版本互连。

```mcfunction
/worldWarp <targets> start <中心x> <中心y> <中心z> <yaw> <pitch> [strength] [periodSeconds]
/worldWarp <targets> followEyes <yaw> <pitch> [strength] [periodSeconds]
/worldWarp <targets> stop [fadeSeconds]
```

| 参数 | 行为 |
| --- | --- |
| 中心 | `start` 使用的固定世界轴上的一点，支持 `~` 相对坐标和 Minecraft 坐标参数；`followEyes` 不传中心 |
| yaw / pitch | Minecraft 方向；yaw 0 朝 +Z，90 朝 -X；pitch 正值向下。`~ ~` 取执行者当前方向并固定下来 |
| strength | 非负强度，默认 1；0 无扭转 |
| periodSeconds | 完整正反往复周期，默认 25 秒（500 tick），最小 0.05 秒 |
| fadeSeconds | 停止时的 smoothstep 渐隐时长，默认 1 秒；0 立即关闭 |

以当前玩家附近为轴心，固定朝 +Z：

```mcfunction
/worldWarp @s start ~ ~1.6 ~ 0 0
/worldWarp @s stop
```

跟随每个目标玩家自己的眼部位置，方向固定朝 +Z：

```mcfunction
/worldWarp @s followEyes 0 0
/worldWarp @a followEyes 0 0 1 25
/worldWarp @s stop
```

`followEyes` 每帧读取目标客户端本地玩家的 `getEyePosition(partialTick)`，包含位置插值和当前姿态眼高。走动、跳跃或蹲伏会移动轴心和零扭转截面；第三人称相机后移、旁观其他实体或演出镜头移动不会改变这个基准。只跟随位置，不随转头改变方向；如需启动时沿执行者视线，可用 `followEyes ~ ~`，方向在命令执行时固定。

命令方块指定同维度玩家、固定轴心和参数：

```mcfunction
/worldWarp @a start 100 65 100 0 0 1 25
/worldWarp @a stop 0
```

`start` / `followEyes` 替换目标玩家的旧参数，从正向零相位重新开始。效果绑定命令执行维度，只向当时处于该维度且支持通道的目标发送。离开维度、退出登录或服务器关闭即清除，不写入存档。`stop` 只影响指定玩家已有的效果；眼部模式在渐隐期间继续跟随。

## 扭转规律

```text
相位 = 2π × (插值后的 tick - 开始 tick) / 周期 tick
距离基准 = start 模式的真实相机 / followEyes 模式的玩家插值眼部位置
角度 = 0.03 × 当前强度 × dot(顶点 - 距离基准, 固定轴方向) × sin(相位)
```

`start` 绕命令定义的世界直线旋转顶点，相机所在的垂直截面不扭转。`followEyes` 绕经过玩家眼部、方向固定的直线旋转，玩家眼部所在的垂直截面不扭转。轴向有符号距离越大，旋转角度越大；没有额外近处截止。参数按渲染帧插值，所有绘制读取同一帧快照。参考固定提交 `0c46c8301fc512c318ac93e23b669355b7d4b180` 的 WARP 距离系数与周期规律；不包含鱼眼、glitch 或噪声。

两种模式均保留真实渲染相机的视图、投影和相机相对坐标。眼部模式仅改变旋转轴心与沿轴距离偏移；CPU 透明排序、保守包围体及 GPU 法线使用同一帧参数，历史重投影使用当前和上一帧各自的眼部基准与真实相机差值。

时间在累加 `partialTick` 前先转为双精度，每帧计算周期相位与渐隐强度，避免较大的世界 tick 经单精度运算吞掉帧间进度。固定轴和眼部跟随模式共用此时间计算。

## 渲染与兼容

本功能限定 Minecraft 1.20.1 / Java 17、Oculus 1.8.0、Embeddium 0.3.31+mc1.20.1 和已核对的 Complementary Unbound r5.9.3：

- 原版 ZIP SHA-256：`98ac741dee294d2a3c82d153349148c3bb7fb688c30eb3b49c3b9ac37e968c5a`。
- 项目开发 ZIP SHA-256：`78c80543179c75cd6beccb93dc86c283cf045a65d5e7fc5cf96e1829db51aede`。
- 在源码加载时核对 ZIP 与必要锚点，内存适配原子应用。不兼容时保留宿主源码，停用扭转并提示一次；不改光影 ZIP、实例配置或依赖。
- 和 Color Loss 顺序组合适配，共用宿主加载及 uniform 入口，不替换后处理链，不增加 GPU 渲染目标。
- 地形、透明方块、水、实体、方块实体、粒子、天气、破坏叠层与选中框在投影和 TAA 抖动前扭转。第一人称手部、HUD、菜单及天空背景保持原样。
- 材质、阴影、体素光照缓存保留原场景坐标；屏幕深度与反射使用变形几何和包含轴向剪切的法线。体积光采样把显示空间位置逆变换后查询原场景。世界空间反射仍在原世界追踪，不模拟弯曲空间中的物理光线路径。
- TAA、反射历史和运动模糊按当前逆变换、上一帧扭转、上一帧投影计算。开启、替换参数、关闭及资源重载时丢弃不连续的历史输入。

主视图使用包含完整旋转范围的保守包围体；活动期间绕过源空间的区块遮挡、遍历方向和面向筛选，阴影通道保持宿主处理。仅处理已加载几何，不改变服务器区块加载距离。

透明排序使用 Embeddium 原有的透明面排序功能（当前实例已开启），不代替被用户关闭的排序功能。保留透明四边形的 CPU 中心数据，使稍后开启效果时无需重建网格；区块任务只更新排序索引，实体透明批次也按变形后的面中心排序。异步任务携带不可变帧快照，仅在宿主接受并上传结果后确认恢复；过期或取消的任务不会提前完成恢复。关闭后沿用宿主排序规则，跨批次绘制仍保留宿主结构。

保守可见范围与持续透明排序会增加效果期间的绘制及 CPU 开销，保留的面中心也占用额外内存。实际走廊观感、跨批次透明边界、反射边缘、第三人称/演出相机以及现有模组组合仍需游戏内确认；独立 GPU 场景和源码编译不代表实机表现。
