# CN3999 RGB 失色系统

权限等级 2，服务端保存与同步，客户端绘制。R、G、B 是三个独立的失色控制量，范围 0～1；颜色逐渐变为灰色，保留明暗，不是把对应 RGB 通道清零。

## 命令

```mcfunction
/colorLoss global color R 1 3
/colorLoss global color G 1 3
/colorLoss global color B 1 3
/colorLoss global all 1 3
/colorLoss global restore 3
/colorLoss global hold
/colorLoss global reset
/colorLoss global status
```

颜色名不区分大小写，兼容 `red/green/blue`。省略时长默认 3 秒，0 为立即修改，上限 3600 秒。时间由服务器 tick 推进，低 TPS 会延长实际时间。新命令从当前强度开始，`color` 只修改对应通道的目标，保留其他目标；三个通道沿用现有的共享过渡时钟。`all` 同时设置三项，`restore` 等同于 `all 0`，`reset` 立即归零，`hold` 冻结当前值并丢弃旧目标。

| 来源颜色 | 对应失色强度 |
|---|---|
| 红、粉、暗红、砖红 | R |
| 橙、黄、棕，包括泥土和木材 | mixed |
| 绿、黄绿 | G |
| 青、蓝绿 | B |
| 蓝、浅蓝 | B |
| 紫、品红 | mixed |

`mixed=max(min(R,G),min(G,B),min(B,R))`，即三个失色强度的中间值。只让一项失色时保留混合色；任意两项失色时，混合色跟随其中较慢的一项褪色，避免只剩一个主色系时仍留下橙棕或紫色。

例如，R=1、G=B=0 时红砖失色而泥土保持棕色；R=1、G=0、B=0.5 时棕色失色一半；R=B=1、G=0 时只保留绿色系，橡木和泥土的棕色变灰。R=G=B=0.5 等价于全画面半失色；三项均为 1 时，本系统输出完全黑白。

青色归入 Blue：仅 B=1 时，青色、浅蓝色和蓝色羊毛的材质色均失色，不再等待 G。青绿交界仍平滑过渡。分层路径与最终画面近似模式共用此分类。

## 材质与照明分层

完整分层路径针对 **Oculus 1.8.0 + Complementary Unbound r5.9.3**。在 ShaderPack 构造时捕获实际加载目录，在 IncludeProcessor 展开源码前完成内存适配，仍由 Oculus 处理选项、预处理、转换、编译和绘制。光影 ZIP、实例配置、宿主后处理链及 framebuffer 布局均不修改。

适配支持以下两个已核对的 r5.9.3 ZIP，按 SHA-256 匹配：

| 光影副本 | SHA-256 |
|---|---|
| 游戏实例原版 | `98ac741dee294d2a3c82d153349148c3bb7fb688c30eb3b49c3b9ac37e968c5a` |
| OverHeaven 开发目录全方向星空版 | `78c80543179c75cd6beccb93dc86c283cf045a65d5e7fc5cf96e1829db51aede` |

开发副本只修改了 `stars.glsl`、`gbuffers_skybasic.glsl` 和 `reflectionBackground.glsl` 的星空坐标与地平线处理；粒子、照明和泛光源码与实例副本一致，失色接入点也相同。加载成功时日志输出 `Color loss: layered source adaptation enabled`；不以同名 ZIP 作为兼容依据。

只处理当前 Oculus 实际加载的源码，其必要锚点必须全部匹配；未被当前版本引用的程序不要求出现在 include graph 中（例如 Oculus 1.8.0 未加载的 `gbuffers_lightning`）。所有改写准备成功后才返回新 include graph。任何版本、指纹或已加载源码的锚点不符时保留整个原 graph，转入最终画面的近似模式，客户端首次使用时提示一次。未开启光影也使用近似模式。近似模式遵守相同 RGB 联动，但无法拆开最终像素中已经混合的材质与照明。

分层路径的关键位置：

- `DoLighting` 保留原输入完成材质参数、法线、粗糙度、自发光强度等计算。最终混合时分别处理材质、已算出的照明和高光，再按原公式组合，并按宿主工作域亮度归一。
- 独立自发光、透明染色、天空、雾、体积光在贡献进入背景前处理。照明后叠加的 `maRecolor` 也单独处理。
- SSR、折射、透明合成继承已处理的场景，不重新选择整个混合结果。新计算的天空反射、体素反射材质/照明及 IPBR 金属反射染色在来源处处理；由已处理画面得到的 LabPBR 染色不再选择一次。
- 体素光照缓存和阴影生产程序保持原始数据，只处理读取缓存后的消费路径。恢复原色无需重建一份失色缓存。
- 已移除扩大红色范围的泛光遮罩、私有遮罩目标及旧的 composite5 采样钩子。宿主泛光直接来自处理后的场景，红色光源中性化后产生中性光晕，覆盖的棕色背景继续正常合成。

红石火把的红色 dust 粒子通过 `gbuffers_textured` 的 `DoLighting` 参与分层失色，保留宿主原有的粒子发光判定与强度；R 失色作用于生成泛光之前的粒子颜色。若日志显示最终画面近似模式，只禁用 R 时已经混合的橙黄色光晕可能作为混合色保留，不能据此认定分层路径已经生效。

多盏灯已经在光照系统内部混成同一种光色时，按混合光色分类，不反推出每一盏灯。

## 分类与色彩编码

Oklab 只用于分类，不额外改变宿主曝光、gamma 或显示转换。纹理和宿主前期工作色使用 sRGB 解码后计算分类；线性体积光使用线性输入。失色输出始终留在该来源原来的工作域，alpha 不变。

| 类别 | Oklab 色相完整区间 | 向下一类平滑过渡 |
|---|---|---|
| 红 | 350°～360°、0°～40° | 40°～52° |
| 橙黄棕 | 52°～104° | 104°～118° |
| 绿 | 118°～168° | 168°～190° |
| 青、蓝 | 190°～288° | 288°～302° |
| 紫 | 302°～338° | 338°～350° |

邻接类别使用 smoothstep，权重之和为 1。相对色度 C/L 在 0.02～0.06 间平滑启用选择性判断，抑制近灰色的不稳定色相；不以低亮度排除暗红。每个来源读取本次失色前的颜色，分类不随已灰化的结果重新变化。红砖的低色度灰缝也遵循此平滑规则。

## 全屏共同强度与历史

每帧在世界绘制前采样一次 RGB，Oculus 的公共 uniform 注册同时覆盖普通物品/实体、Embeddium 地形和 composite 程序。

共同强度 `base=min(R,G,B)` 留到光影结束后统一灰化。base<1 时，来源分层使用 `residual=(RGB-base)/(1-base)`；base=1 时关闭选择性来源处理，最终直接输出灰度。三项同值时仅执行统一的全屏渐变，避免来源灰化重复累积。

最终合成位置仍为 Forge 47.4.10 的 `GameRenderer.renderLevel` 返回之后，包含 Oculus 最终颜色空间转换和 EndingLibrary 的 levelEffect。原版后处理、OverHeaven 传送/终章屏幕效果和 HUD 在此后执行，后续效果仍可能生成自己的彩色内容；本系统不替换或重排这些链路。

普通渐变保留宿主 TAA。零秒修改、重置、首次状态、维度切换、资源重载及渐变首次抵达终点时，当前世界帧直接刷新现有 TAA 与反射历史，避免继续混入旧颜色。未实际绘制世界的加载/菜单帧不会消耗重置请求。周期校时不会反复触发同一终点重置。

手部与世界遵守相同分层规则；HUD、聊天和菜单不直接参与。选择性分层无需私有全屏颜色副本；仅共同强度或近似模式使用原有的一次颜色复制及一次合成。零强度跳过绘制，不需要最终合成时释放其 GPU 资源；重载、卸载和关闭释放资源。渲染异常会记录错误并停用，资源重载后重试。

## 玩家覆盖、存档与协议

```mcfunction
/colorLoss players @a[tag=audience] all 1 5
/colorLoss players @s color B 1 2
/colorLoss players @s restore 2
/colorLoss players @s hold
/colorLoss players @s status
/colorLoss players @s inherit
```

全局默认影响当前和后来加入的跟随者；单独覆盖跨死亡、重连和维度切换保留。全局命令不改写已有覆盖；玩家 restore/reset 仍保留单独覆盖，需要 `inherit` 才重新跟随全局。

主世界 SavedData `overheaven_color_loss` 升级为 **version=2**，保存三项 RGB 与原有渐变时钟、玩家覆盖。读取旧 360 点曲线时，仅抽取 0°、120°、240° 分别作为 R/G/B，迁移起止值并保留起始 tick、时长和玩家覆盖。旧曲线的宽范围残留不再参与分类，后续保存写回 v2。

网络频道 `color_loss` 协议升级为 **2**，快照含两组 RGB、经过 tick 和时长；旧协议客户端与服务端不能混用。未安装此模组的客户端仍按原有可选连接策略处理，不会收到效果包。登陆、维度切换、复活同步快照，渐变期间每 20 tick 校时。

独立验证入口保留在 `src/verification`：状态/迁移/协议/时钟、原版纹理与独立 GPU 合成，以及实际 ZIP 经 Oculus 预处理和转换后的 shader 编译。它们不启动游戏，也不代表已经完成真实光影、反射边缘或其他模组叠加的游戏内验收。
